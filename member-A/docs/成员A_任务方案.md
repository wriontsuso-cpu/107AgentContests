### 3.2 数据清洗与结构化

#### 资源实体模型（供全员对齐）

```json
{
  "id": "uuid",
  "title": "资源名称",
  "summary": "一句话简介（≤200字）",
  "url": "https://...",
  "category_id": "cat_xxx",
  "tags": ["免费", "二课", "留学"],
  "source_type": "crawl|curated|questionnaire|interview",
  "source_name": "学工在线-奖助学金",
  "access_type": "public|login_required|external",
  "cost": "免费 / 教育优惠 / …",
  "how_to": "获取/使用方式",
  "audience": ["本科", "研究生", "新生"],
  "published_at": "2026-08-14",
  "updated_at": "2026-08-20",
  "relevance_score": 0,
  "status": "active|deprecated"
}
```

#### 清洗规则

| 规则 | 处理 |
|------|------|
| URL 去重 | 同一 URL 保留最新 `updated_at` |
| 标题去重 | 相似度 >0.9 合并，保留信息更全的一条 |
| 空链接 | 标记 `status=deprecated`，不进入检索 |
| 导航项误抓 | 过滤「首页」「更多>>」等（已在 parser 实现） |
| 编码/乱码 | 统一 UTF-8，摘要截断 500 字 |

**产出脚本：**

- `scripts/clean_and_import.py`：读 `output/student_resources.json` → 写入 DB
- `scripts/dedupe_report.txt`：去重前后数量对比

### 3.3 数据库搭建

#### 推荐选型（与 B 对齐后二选一）

| 方案 | 优点 | 适用 |
|------|------|------|
| **SQLite** | 零部署、Demo 快 | 初赛 / 本地演示 |
| **PostgreSQL** | 并发、全文检索、pgvector | 决赛 / 向量检索同库 |

#### 表结构（最小集）

```
categories          # 分类树
  id, parent_id, name, level, path, sort_order

tags                # 标签词典
  id, name

resources           # 资源主表
  (见上方实体模型字段)

resource_tags       # 多对多
  resource_id, tag_id

resource_sources    # 采集批次/溯源
  id, resource_id, batch_id, raw_url, crawled_at

sync_state          # 增量同步
  url, last_seen_at, hash
```

#### 维护脚本

| 脚本 | 功能 |
|------|------|
| `db/init.sql` | 建表 |
| `db/seed_categories.sql` | 导入分类树 v1 |
| `scripts/import_json.py` | JSON → DB |
| `scripts/export_api_json.py` | DB → B/C 用的 `api/resources.json` |

#### 只读 API（供 C 前端，M3 交付）

```
GET /api/categories/tree
GET /api/resources?category=&tag=&q=&page=
GET /api/resources/{id}
```

实现可用 FastAPI 薄封装，或先导出静态 JSON 给 C 联调。
