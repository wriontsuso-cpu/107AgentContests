# 数据二次清理与 AI 问答页改版设计

日期：2026-09-01  
状态：用户已在对话中确认需求；仅在隔离工作区实施，晚间验收前不得提交、合并或上传。

## 范围

本轮包含四项工作：

1. 基于最新全量 HTTP 探活数据二次清理资源目录。
2. 让首页与资源大厅的总数、一级分类数量自动跟随发布数据更新。
3. 将 AI 回复从 Markdown 源文本改为安全、完整、可读的 Markdown 渲染结果。
4. 将 AI 问答页改为低饱和背景上的沉浸式整页对话，并把历史记录改为可收起侧栏。

首页动画不属于本轮范围，等待用户晚间继续说明。

## 数据清理

### 输入与保留原则

- 以远端数据分支 `origin/数据补充与更新` 的最新探活数据为输入，保留未经清理的原始审计数据作为可恢复来源。
- 登录墙、CAS、403 或仅限校内网络的资源不删除，发布时保留状态说明。
- `mailto:` 资源保留并标为“发送邮件”。
- 本地离线文档仅在仓库内目标文件真实存在时保留；缺失文件视为不可访问资源。

### 排除原则

- 删除 `url_status=dead` 的资源。
- 删除 `url_status=unknown` 的资源。
- 删除空标题、空 URL 等无法展示的记录。
- 对高风险模式进行真实浏览器定向复核，最终落到无关首页、通用下载页、错误内容或浏览器错误页的资源删除。
- `i.ustc.edu.cn/page/site/noticeDetail/...` 和 `noticeAnnouncementDetail` 若最终进入 CAS，则按“需要登录”保留；旧 404 路由不发布。
- `i.ustc.edu.cn/appDetail/...` 等已知会跳到通用 APP 下载页的路径，找不到确定替代详情页时删除。

### 高风险复核边界

不重新用浏览器全量检查 12,882 条。复核集中在：

- `appDetail`、旧 SPA 路由和通用页面回退；
- 探活最终地址与原地址明显不相干的重定向；
- `blocked`、`reachable` 中已经观察到 HTTP 与浏览器行为不一致的集中模式；
- 本地文件存在性。

清理逻辑必须是确定性脚本，并输出排除原因统计，保证重复运行得到同一结果。

### 发布数据

- 权威 JSON、带 `search_text` 的后端 JSON 和前端紧凑快照从同一清理结果生成。
- 前端投影保留 `url_status`、`url_http`、`url_err`、`url_checked_at`，以便展示访问提示。
- 后端知识库不得加载被排除记录。
- 现有搜索权重、模糊匹配和别名策略保持不变；删除资源不通过降权替代。

## 动态数量

当前 `frontend/src/data/catalogMetadata.ts` 写死为旧目录的 1,295 条统计，这是资源大厅左栏数字过期的根因。

数据生成脚本将额外生成轻量目录元数据，其中包含：

- 清理后的可发布总数；
- 各一级分类数量；
- 生成时间和数据版本。

首页资源总数和资源大厅左侧分类树统一读取该元数据。页面不直接为计算数字而提前加载 10 MB 以上的完整资源快照，从而避免拖慢首页首屏。测试校验总数等于分类数量之和，也等于适配器实际加载数量。

## Markdown 渲染

AI 回复支持：段落、标题、粗体、斜体、有序/无序列表、引用、链接、行内代码、代码块和表格。

- AI 消息使用 Markdown 渲染，用户消息继续按纯文本展示。
- 禁止原始 HTML，避免模型输出注入页面结构或脚本。
- 外部链接新窗口打开，并设置安全的 `rel` 属性。
- 标题、正文、列表、引用、代码和表格分别设置清晰字号、行高、留白与对比度。
- 推荐资源卡和澄清选项仍是结构化组件，不混入 Markdown HTML。
- 空内容、异常 Markdown 和长代码块不得破坏对话布局。

## AI 问答页布局

### 页面结构

- 背景图覆盖完整对话页面，使用低饱和处理、柔和遮罩和受控模糊，文字区域保持足够对比度。
- 移除包围整个聊天区的暖色圆角玻璃卡片。
- 助手消息直接排在主画布的阅读列中，以头像、署名、排版和轻微分隔线建立层级，不使用大气泡。
- 用户消息靠右显示，可保留非常轻的底色或短下划线，但不使用厚重圆角气泡。
- 输入区固定在底部阅读列内，采用轻薄半透明横条；保留明确的输入边界、键盘操作和发送状态。
- 快捷提问、错误提示、登录提醒和资源推荐保留必要的交互边界，但减少圆角和阴影。

### 历史记录

- 桌面端使用左侧可收起窄栏，默认收起为一个会话图标，展开后显示新建会话、搜索和最近会话。
- 移动端使用抽屉，不永久占据内容宽度。
- 展开/收起保持键盘可操作、焦点可见，并提供正确的 `aria-expanded`、标签和关闭行为。
- 需求线索不再占据固定大侧卡，可在阅读列顶部以紧凑摘要呈现，或在历史栏中作为次级区域。

### 背景候选

先使用仓库已有、来源已登记的素材制作至少三种候选预览：

1. 夜间书桌插画：氛围集中，但需显著降低细节干扰。
2. 中国科大雪后校园实景：学校辨识度高，整体偏冷静。
3. 林荫校园步道或校园草坪：更轻盈自然，适合浅色文字画布。

晚间由用户查看实际页面后决定最终图片。实施阶段不得擅自上传新图片或确定最终候选。

## 错误处理与验证

- 数据脚本输出保留、删除及各删除原因数量；任何 ID 重复、分类未映射或统计不一致均使脚本失败。
- 单元测试覆盖清理策略、登录资源保留、本地文件判断、动态统计和审计字段适配。
- 组件测试覆盖 Markdown 语法、安全链接、HTML 禁止、历史栏开关和无卡片对话结构。
- 运行前端完整测试、lint、生产构建和后端测试。
- 使用本地预览检查桌面与移动宽度、长回复、滚动、历史栏和背景可读性。
