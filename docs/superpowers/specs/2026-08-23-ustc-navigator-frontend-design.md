# USTC Navigator 前端设计说明

## 1. 目标与范围

成员 C 交付一个面向中国科大新生和本科生的响应式 Web 前端，通过分类探索、关键词检索、资源详情和 AI 助手外壳展示校园资源。首版必须能在后端尚未完成时用 Mock 数据完整演示，并能在后端 API 就绪后只替换数据适配层。

首版包含四个路由：

- `/`：首页与八类资源探索门户。
- `/resources`：资源大厅、两级分类、搜索、标签筛选和分页。
- `/resources/:id`：内部资源详情与官方来源跳转。
- `/assistant`：AI 对话外壳、追问选项和推荐资源卡片。

首版不包含登录、收藏、个人画像、复杂知识图谱、校区筛选和适用人群筛选。校区与人群字段在正式数据可靠提供后再扩展。

## 2. 视觉与交互方向

视觉命题：以中国科大官方视觉资产为可信锚点，打造具有编辑感与探索感的校园资源门户。界面高级、明亮、克制，避免常见 AI 产品的荧光渐变、悬浮玻璃卡片堆叠与模板化文案。

- 品牌使用 `USTC Navigator`，中文副标题为“科大校园资源导航助手”。
- 科大蓝作为唯一主强调色，八个分类仅使用低饱和辅助色区分。
- 团队已取得使用中国科大官方素材的许可。首屏可使用来自学校官网的校徽、标准校名与校园照片；所有素材保留来源记录，不采用非官方转载图。
- 首屏以一张高质量校园照片做全宽视觉锚点，在照片上叠加克制的路径/节点纹理，表达“从需求抵达资源”，但不遮挡主体建筑。
- 页脚持续标注“学生参赛项目”，并避免使用“官方平台”“校务系统”等容易混淆产品身份的措辞。
- 字体使用本机中文系统字体与英文无衬线字体，不依赖外部字体 CDN。
- 动效只保留三类：首屏路径缓慢进入、分类入口悬停反馈、页面与列表的短距离淡入；支持 `prefers-reduced-motion`。

首页首屏包含产品名、两行以内说明、全局搜索和 AI 入口。其下完整展示八个一级分类；桌面端采用有层次的八宫门户，移动端重排为两列。悬停或聚焦时展示二级栏目摘要，点击后进入 `/resources?group=<groupId>`。

## 3. 信息架构

前端固定八个一级分类，并把现有 32 个原始栏目映射为二级分类：

1. 办事与公共服务：财务服务、资源导航、学工通知、保卫服务、教务服务、校级通知、办事指南、公示公告、网站入口。
2. 学习与学术：图书馆、教务通知、图书馆资源、教务选课、免费软件-会员。
3. 科研与创新：超算中心、学术科研、会议-学术交流。
4. 竞赛与实践：竞赛-科创、勤工助学。
5. 社团与校园活动：校园活动、青春科大、二课-团学活动、媒体关注。
6. 生活设施：迎新资讯、新生指南、新生事务。
7. 身心健康与权益：校医院、奖助学金。
8. 升学就业与国际交流：研究生培养、本科招生、留学-国际交流、留学-出境交流、就业实习。

未识别的新栏目进入“其他资源”，页面不得因此报错。映射保存在单一配置文件中，等待 A/D 确认后可独立调整。A 分支现有 6 类 Mock 只作为数据来源，不决定最终首页一级分类。

## 4. 组件与页面

- `AppShell`：桌面与移动导航、页面宽度和全局错误边界。
- `HeroSearch`：首页搜索提交后进入资源大厅并携带 `q` 参数。
- `CategoryPortal`：八类探索入口，支持鼠标、键盘和触摸操作。
- `CategoryTree`：资源大厅两级分类；移动端放入筛选抽屉。
- `ResourceCard`：统一展示标题、摘要、分类、来源、标签和权威标识。
- `ResourceDetail`：展示正文、获取方式、费用、来源、更新时间和官方链接；缺失模块直接隐藏。
- `AssistantShell`：展示欢迎状态、用户/助手消息、追问选项、加载、错误、无答案和推荐结果。
- `EmptyState` 与 `ErrorState`：为无数据、请求失败、资源不存在提供明确下一步操作。

普通资源卡点击内部详情页；“前往官方页面”在新标签页打开数据集中的已知 URL。AI 返回内容不得把模型自由生成的 URL 渲染成可点击链接。

## 5. 数据契约与适配

页面只消费统一的前端类型，所有 Mock、静态 JSON 和后端响应先经过适配器：

```ts
type Resource = {
  id: string
  title: string
  summary: string
  content?: string
  officialUrl: string
  source: string
  category: string
  groupId: string
  tags: string[]
  authorityLabel?: string
  howTo?: string
  cost?: string
  publishedAt?: string
  updatedAt?: string
}
```

- A 分支 Mock 中的 `id` 直接使用。
- 正式 JSON 暂无 `id` 时，适配器根据规范化 URL 生成稳定 ID；后端正式提供 ID 后优先使用后端值。
- `summary` 为空时显示“暂无简介，请查看官方来源”；`content`、`howTo`、`cost` 为空时隐藏对应区块。
- 未知分类进入 `other`；非法或非 HTTP(S) URL 不显示外链按钮。

目标 API：

- `GET /api/categories`
- `GET /api/resources?q=&group=&category=&tag=&page=&page_size=`
- `GET /api/resources/{id}`
- `POST /api/search`

AI 响应状态为 `clarify`、`results`、`no_answer` 或 `error`。在真实接口可用前，API 客户端读取本地 Mock；运行时通过 `VITE_API_BASE_URL` 和 `VITE_USE_MOCKS` 切换，页面组件不感知数据来源。

## 6. 错误处理与安全

- 请求显示骨架加载，超时或服务失败显示重试操作。
- 未找到资源返回专用 404 状态，并提供返回资源大厅按钮。
- 官方链接使用 `target="_blank"` 与 `rel="noopener noreferrer"`。
- 大模型 API Key 永不进入前端仓库；浏览器只调用 B 的后端。
- 前端不渲染 AI 返回的原始 HTML，不执行数据内容中的脚本。
- 1295 条正式数据不直接打包进生产前端；开发 Mock 只保留足以覆盖状态的样例。

## 7. 响应式、无障碍与性能

- 验证 1920×1080、1366×768 和 390px 手机宽度。
- 支持当前 Chrome 与 Edge。
- 所有交互可使用键盘完成，焦点可见，图标按钮有可访问名称。
- 色彩不作为唯一信息编码，正文和按钮达到可读对比度。
- 资源列表分页加载；路由页面懒加载；动画不阻塞输入和导航。

## 8. 测试与验收

单元/组件测试覆盖：分类映射、资源适配、稳定 ID、搜索参数、空字段降级、非法 URL、分类树和资源卡。

Playwright 覆盖：

1. 首页八个分类均可见并可进入相应资源大厅。
2. 搜索、分类和标签组合后 URL 与结果同步。
3. 资源卡进入内部详情，官方链接具有安全属性。
4. 不存在的资源显示可恢复的 404 状态。
5. AI Mock 完成“模糊需求—追问—推荐—详情”闭环。
6. 桌面端和手机端无水平溢出，核心操作可用。

交付前必须通过类型检查、单元测试、生产构建和 Playwright 核心流程。

## 9. 与队友的边界

- A：提供增量采集、结构化资源、稳定 ID 和分类/字段说明。
- B：提供资源浏览、详情、AI 检索 API，并在后端完成推荐 URL 校验。
- C：负责本设计中的全部前端、Mock/真实 API 适配和前端测试。
- D：确认接口、完成部署与跨模块联调，并将 6 类/8 类分类差异提交团队定稿。

新增爬虫数据只要遵循字段规范即可通过适配器显示；增加资源不需要修改页面。新增字段或变更枚举必须先更新接口规范。
